## Top 10 highest-risk outdated assumptions

1. A pCID is permanently identical to a frozen prose/doc CID. CD Int now treats the exact pCID-root/manifest publication model as unresolved.
2. The visible signed `grid([42(pCID), payload, proof])` specimen is a universal envelope/signature requirement. Proof and arity are pCID-defined.
3. A CID link proves dependency, availability, trust, retention, authority, merge, or safety. Generic links only expose unlabeled graph structure.
4. A valid signature yields acceptance or proves an actor is globally current. Acceptance, freshness, authorization, and trust are local decisions.
5. A repository/component has one globally latest/current head. Heads must identify both the publisher/observer and whether they are known or accepted.
6. A storage replica owns, may write, or is the authoritative location of another agent’s repository. Storage commitments/receipts are the storage agent’s own promises.
7. Sparse CAS CID knowledge means retrievable/replayable bytes. Availability and retention require separate evidence; replay-critical closure should fail closed otherwise.
8. “Rebuildable” means any cache/index/database can be regenerated somehow. A defensible rebuild needs named source frontier, functions, policy/context, and retained closure.
9. A request/result receipt proves an external mutation, or retry after uncertain result is safe. CD Int requires attempt, result, targeted readback, reconciliation, and append-only correction evidence.
10. Publishing a release automatically updates components or “rollback” restores the world. Hosts choose local adoption; corrective roll-forward/restore is not historical rewrite or guaranteed external undo.

## Dev Guide sections probably still safe as written

- `README.md` introduction and reading order: guide first, then upstream evidence; frozen pCID references prevail over simulations/drafts.
- App Devs: avoid a universal app API; use protocol-owned semantics and scoped implementation claims.
- Kernel Devs: do not invent a global trust score or make the kernel decide application promise keep/break.
- Kernel Devs: layered/binding/session/message/CAS guidance is orientation, not a frozen ABI or universal wrapper.
- pCID-as-not-address / pCID-only dispatch cautions, provided the text remains clear that exact proof requirements are pCID-defined.
- Component boundary guidance that a helper becomes externally relevant when other actors must rely on its public protocol behavior.
- The broad CAS discipline that byte-addressed content is not merely an incidental cache—so long as it does not imply one frozen physical layout or universal availability.

## Evidence conflicts and limits

- NINIK says a genesis-event-CID AgentID launch profile was selected; current `GLOSSARY.md` calls AgentID Draft and `DN-jibut` retains DID method/freshness/failover questions under `DR-popor`. This report therefore classifies public identity elaboration as refinement, not a final normative change.
- NINIK recommends predecessor-linked repository commits/reference-set patterns, but its own decision table says exact repository succession/layout needs DF under `DR-baguj`; current glossary also marks both Draft. No final repository schema is inferred.
- NINIK treats component publication/adoption reuse as a high-confidence direction, but current runtime-root and executable-descriptor documents are draft and stage0 selection remains open. No automatic update/rollback contract is inferred.
- Current Go code under `x/cas-native-index` is experimental evidence, not a public wire protocol. It demonstrates patterns (notably readback/reconciliation and interrupted-publication repair) without freezing field names, transport, storage layout, or operation taxonomy.
