# Overall conclusion

**The public PromiseGrid work is substantially aligned with CD Int; this is not a wholesale model reversal.** The biggest changes are production-hardening refinements: sharper identity boundaries, clearer separation of protocol semantics from execution identity, explicit local acceptance/freshness, stronger storage and recoverability evidence, reproducible derivation boundaries, and first-class external-effect readback/reconciliation.

## Critical: External effects, readback, reconciliation, and retry

Both comparisons converge on the same operational safety lesson: recording intent, sending a request, receiving a response, or storing an action hash is not enough to establish what happened in an external system.

| **Dev Guide impact**         | **The Dev Guide currently uses receipts/witnesses as evidence for physical/workflow effects; CD Int makes intent, attempt, response, readback, reconciliation, and correction distinct evidence. Uncertain results require read-before-retry.** |
|------------------------------|-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **Wire Lab impact**          | Wire Lab already has ordered journal/action-hash patterns, but CD Int tightens them with source snapshot/key, approval, request/response, immediate readback, retry criteria, and correction evidence.                                          |
| **Why it matters**           | This is the clearest area where an implementation can cause duplicate or unsafe external actions if old wording is interpreted too loosely.                                                                                                     |
| **Open decision / question** | Open: exact public representation and when automatic retry is permitted.                                                                                                                                                                        |
| **Source classification**    | Synthesized from the two comparison reports; project-specific evidence is preserved in the appendices.                                                                                                                                          |

## High: Agent identity is separate from signing keys, machines, processes, and repositories

CD Int makes AgentID a distinct identity concept. The public material should not let a local name, signer key, process, machine, app role, repository commit, or deployment stand in for the agent itself.

| **Dev Guide impact**         | **The Dev Guide’s agent definition is broadly sound but does not develop identity lifecycle/freshness deeply enough. Current CD Int keeps the exact method/profile partly open.** |
|------------------------------|-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **Wire Lab impact**          | Wire Lab POC18/20 examples use signer/local identifiers that are appropriate for POCs but could be over-read as durable cross-repository identity.                                |
| **Why it matters**           | Key rotation, recovery, copied-key forks, identity resolution, and freshness become ambiguous if identity is collapsed into the signer.                                           |
| **Open decision / question** | Open: durable AgentID method/profile, rotation/recovery, and freshness evidence.                                                                                                  |
| **Source classification**    | Synthesized from the two comparison reports; project-specific evidence is preserved in the appendices.                                                                            |

## High: pCID selects protocol meaning; execution identity is separate

A pCID identifies protocol semantics. Exact executable artifacts, dependency closure, runtime, and other replay evidence are separate concerns.

| **Dev Guide impact**         | **The Dev Guide’s “pCID = frozen spec/doc CID” shorthand is useful but may overstate a still-open publication/manifest identity choice. Its signed three-slot envelope example can also look universal.** |
|------------------------------|-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **Wire Lab impact**          | Wire Lab POC20 allows function definitions/executables by CID; CD Int sharpens the separation between protocol pCID, function definition, executable descriptor, dependencies, and execution environment. |
| **Why it matters**           | Without this distinction, implementation upgrades can accidentally look like protocol changes, and replay claims can be weaker than they appear.                                                          |
| **Open decision / question** | Open: public terminology for prose/spec/manifest pCID identity and which generic envelope claims are stable.                                                                                              |
| **Source classification**    | Synthesized from the two comparison reports; project-specific evidence is preserved in the appendices.                                                                                                    |

Generic tag-42 CID scanning exposes graph edges but does not automatically assign semantic labels.

|------------------------------|----------------------------------------------------------------------------------------------------------------------------------------------------------|
| **Wire Lab impact**          | Wire Lab’s typed parent links are valid inside their selected protocols; generic indexing must not infer those typed meanings from link structure alone. |
| **Why it matters**           | This protects generic infrastructure from silently inventing application semantics.                                                                      |
| **Open decision / question** | No major open decision beyond keeping generic and pCID-owned semantics distinct.                                                                         |
| **Source classification**    | Synthesized from the two comparison reports; project-specific evidence is preserved in the appendices.                                                   |

## High: Local acceptance, freshness, and “latest” are receiver-specific

A valid signature, discovered candidate, or published head is not automatically trusted, fresh, authorized, or accepted. There is no single global current head.

| **Dev Guide impact**         | **The Dev Guide already rejects global trust scores, but should consistently distinguish known versus locally accepted and qualify “latest/head/current.”**      |
|------------------------------|------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **Wire Lab impact**          | Wire Lab already strongly reflects local trust/no-global-authority; examples should consistently say “accepted by whom” and not let sync imply shared authority. |
| **Why it matters**           | This prevents centralized latest-value assumptions from reappearing inside an otherwise decentralized model.                                                     |
| **Open decision / question** | Open: how broadly public guidance should formalize local-acceptance/freshness warnings.                                                                          |
| **Source classification**    | Synthesized from the two comparison reports; project-specific evidence is preserved in the appendices.                                                           |

## High: Storage, availability, retention, shareability, and ownership are separate

A CID, replica, or storage receipt does not automatically establish availability, promised retention, ownership, shareability, or repository authority.

| **Dev Guide impact**         | **The Dev Guide needs a stronger distinction between logical CID identity, actual possession, retention/serve promises, and physical storage format/recoverability.**          |
|------------------------------|--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **Wire Lab impact**          | Wire Lab is already close: shareability and local retention are distinct, but CD Int makes owner repository vs. storage-agent evidence and closure availability more explicit. |
| **Why it matters**           | Recovery and replay can fail if a root exists but its closure is not actually available or retained.                                                                           |
| **Open decision / question** | Open: lifecycle semantics, retention requirements, and recovery gates.                                                                                                         |

## High: Pure derivation and rebuildable views require explicit provenance

|------------------------------|------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **Wire Lab impact**          | Wire Lab POC20 already has deterministic inputs/context and local verification; CD Int adds exact execution closure, prior heads/frontier, policy/trust context, and external observations where relevant. |

## High: Publication, local adoption, capabilities, and runtime roots must stay separate

| **Wire Lab impact**          | Wire Lab’s runtime-root/stage0 direction is substantially aligned; CD Int adds more explicit impact review, host capabilities, closure evidence, and adoption history. |

## High: Rollback means correction/restore attempt, not erasure

History remains true even when a later action tries to restore an earlier state. External effects may not be reversible.

| **Dev Guide impact**         | **The Dev Guide should avoid presenting rollback as a universal guarantee while runtime-root/update semantics remain draft.**   |
|------------------------------|---------------------------------------------------------------------------------------------------------------------------------|
| **Wire Lab impact**          | Wire Lab already states that true rollback is generally unavailable after side effects; this should be retained and reinforced. |
| **Why it matters**           | This avoids false claims that selecting an older root undoes purchases, device actions, peer state, or external writes.         |

## Top 10 highest-risk outdated assumptions

1.  A pCID is permanently identical to a frozen prose/doc CID. CD Int now treats the exact pCID-root/manifest publication model as unresolved.

2.  The visible signed grid(\[42(pCID), payload, proof\]) specimen is a universal envelope/signature requirement. Proof and arity are pCID-defined.

3.  A CID link proves dependency, availability, trust, retention, authority, merge, or safety. Generic links only expose unlabeled graph structure.

4.  A valid signature yields acceptance or proves an actor is globally current. Acceptance, freshness, authorization, and trust are local decisions.

5.  A repository/component has one globally latest/current head. Heads must identify both the publisher/observer and whether they are known or accepted.

6.  A storage replica owns, may write, or is the authoritative location of another agent’s repository. Storage commitments/receipts are the storage agent’s own promises.

7.  Sparse CAS CID knowledge means retrievable/replayable bytes. Availability and retention require separate evidence; replay-critical closure should fail closed otherwise.

8.  “Rebuildable” means any cache/index/database can be regenerated somehow. A defensible rebuild needs named source frontier, functions, policy/context, and retained closure.

9.  A request/result receipt proves an external mutation, or retry after uncertain result is safe. CD Int requires attempt, result, targeted readback, reconciliation, and append-only correction evidence.

10. Publishing a release automatically updates components or “rollback” restores the world. Hosts choose local adoption; corrective roll-forward/restore is not historical rewrite or guaranteed external undo.

## Top 10 highest-risk outdated assumptions

21. A signer/key/local role is the durable agent identity. CD Int separates AgentID, key, process, machine, and repository commit; its identity method remains open.

22. A pCID identifies the code that executed an event. It identifies protocol semantics; audit/replay needs separately identified executable and dependency closure.

23. A generic CID link carries parent/ownership/retention semantics. Generic scanning yields structural edges only; selected pCIDs supply semantic labels.

24. A runtime root CID proves recoverability or authorizes adoption. It names bytes; local adoption, signer/policy checks, host-capability review, and closure availability/retention evidence are separate.

25. “Replay” can safely rerun an old external action. Historical verification, pure recomputation, and side-effect reconciliation are different operations.

26. An external write is established by sending an action or storing an action hash. CD Int’s refinement needs source key/snapshot, approval, request/response, readback, retry, and correction evidence.

27. A storage receipt makes the storage agent repository authority. The owner publishes its repository; the storage agent publishes its own retain/serve evidence.

28. Continuous sync implies safe convergence of authority. It does not resolve split brain, exclusive-writer handoff, or partitioned shared resources; fencing/lease/quorum/capability remains open.

29. Every message must have a stand-alone signature. CD Int treats individual, aggregate, and hybrid authentication as pCID-specific alternatives still requiring measurement/decision.

30. A capability token, manifest, or discovered implementation CID grants ambient authority. Each resource controller must locally approve/redeem bounded authority; parsing and discovery do not authorize effects.

## Bottom line

Wire Lab’s later POC18–POC21 direction is substantially aligned with the available CD Int design: pCID-defined semantics, local acceptance, parent-linked evidence, no global truth, CAS event sources, rebuildable views, local adoption, and corrective rather than erasing history. The main gap is not a wholesale model reversal. It is a production-hardening refinement around durable identity, separating semantic pCIDs from exact execution closure, treating generic CID links as structural only, making storage/availability evidence explicit, and making external effects/readback/reconciliation first-class. Several exact schemas remain open; the report intentionally does not turn them into decisions.
